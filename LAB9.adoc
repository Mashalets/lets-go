== Архитектура NVIC и EXTI 

В микроконтроллерах STM32F4, построенных на базе ядра Cortex-M4, управление прерываниями осуществляется аппаратным модулем NVIC (Nested Vectored Interrupt Controller). Этот контроллер встроен в процессорное ядро и отвечает за обработку множества аппаратных прерываний, обеспечивая гибкую систему приоритетов. В STM32F411 доступно 82 маскируемых канала прерываний (IRQ), каждый из которых связан с определённым периферийным устройством (например, таймер, UART, DMA) либо с внешними прерываниями, поступающими через блок EXTI.

NVIC поддерживает вложенные прерывания, что позволяет обработчику с более высоким приоритетом прервать выполнение обработчика с более низким приоритетом. Уровни приоритета задаются 4-разрядным значением: чем меньше число, тем выше приоритет (0 — максимальный, 15 — минимальный). Помимо этого, система приоритетов может быть разделена на группы, где часть битов отвечает за основной приоритет, а другая — за подприоритет, однако по умолчанию используется только основной приоритет.

=== Контроллер внешних прерываний EXTI

EXTI (External Interrupt/Event Controller) — это модуль, отвечающий за обработку сигналов, поступающих на определённые выводы микроконтроллера. Он позволяет отслеживать изменения на линиях GPIO и передавать запросы прерываний в NVIC. По своей структуре EXTI действует как мультиплексор, который принимает сигналы от различных портов (PA, PB, PC и т. д.) и направляет их в систему прерываний.

Контроллер EXTI в STM32F4 включает 16 линий, каждая из которых может быть связана с конкретным выводом (например, EXTI5 можно подключить к PA5, PB5 или PC5). Линии могут реагировать на изменения сигнала по фронту, спаду или обоим фронтам.

Когда на одной из линий происходит событие, соответствующий флаг pending в EXTI устанавливается, сигнализируя о необходимости обработки. Затем, если данная линия разрешена в NVIC, контроллер передаёт запрос прерывания на соответствующий канал. Если прерывания глобально включены, NVIC принимает этот запрос и передаёт управление обработчику прерывания, который вызывается по адресу, хранящемуся в таблице векторов.

=== Взаимодействие NVIC и EXTI

Когда поступает прерывание, NVIC проверяет его приоритет, чтобы определить, можно ли его выполнить немедленно или необходимо дождаться завершения текущего обработчика. Если прерывание разрешено и его приоритет выше, чем у выполняемого кода, процессор сохраняет текущее состояние и передаёт управление соответствующей функции обработки.

Стоит учитывать, что не каждая линия EXTI имеет отдельный IRQ. Например, линии 0–4 имеют индивидуальные каналы прерываний (EXTI0_IRQn, EXTI1_IRQn и т. д.), но линии 5–9 объединены в общий канал EXTI9_5_IRQn, а линии 10–15 — в EXTI15_10_IRQn. Это означает, что при срабатывании нескольких линий из диапазона 10–15 одновременно вызывается один и тот же обработчик. Внутри него необходимо проанализировать, какие флаги pending установлены, и обработать их поочерёдно.

NVIC также поддерживает механизм tail-chaining, который минимизирует задержки при переключении между обработчиками прерываний. Если одно прерывание завершается, а следующее уже ожидает исполнения, переход к нему осуществляется без возврата в основной код. В случае одновременного поступления нескольких запросов с одинаковым приоритетом NVIC обслуживает тот, у которого меньший номер IRQ.

Таким образом, взаимодействие NVIC и EXTI позволяет гибко управлять внешними сигналами, обеспечивая обработку событий в реальном времени. Это особенно важно для таких задач, как работа с кнопками, датчиками или другими периферийными устройствами, требующими быстрой реакции со стороны микроконтроллера.

== Роли и связи классов в проекте

Архитектура проекта основана на принципах объектно-ориентированного программирования и использует шаблонные механизмы для повышения гибкости и переиспользуемости. Компоненты системы функционируют независимо и взаимодействуют через вызовы методов.

=== Компоненты системы

* *`ButtonExti`* — шаблонный класс, отвечающий за обработку внешних прерываний.  
  При активации передаёт управление методу `SwitchModeManager` соответствующего менеджера режимов.
  
* *`ModeManager`* — управляет активным режимом работы системы,  
  обеспечивая переключение между различными вариантами (например, `AllMode`, `ChessMode`, `TreeMode`)  
  и выполняя обновление текущего состояния.

* *`Timer`* — универсальный шаблонный класс, привязанный к аппаратному таймеру (`TIM2`, `TIM5`).  
  Формирует периодические события прерывания, которые вызывают метод `UpdateModeManager`.

=== Взаимодействие компонентов

Центральным элементом архитектуры является *`ModeManager`*, который координирует работу системы,  
реагируя как на нажатие кнопки (через `SwitchModeManager`), так и на сигналы от таймера (через `UpdateModeManager`).  
Это позволяет динамически менять состояние в ответ на события, обеспечивая гибкость работы всей системы.

== Настройка EXTI13 для обработки кнопки

Для корректной обработки нажатия кнопки необходимо правильно сконфигурировать линию EXTI13. Этот процесс включает несколько последовательных этапов:

. Установка пина 13 порта GPIOC в режим входа.
. Включение тактирования SYSCFG для работы с внешним источником прерывания.
. Настройка связи между EXTI13 и выводом PC13 через регистр SYSCFG_EXTICR4.
. Активация детектора по спадающему фронту.
. Разрешение работы линии в маске EXTI_IMR.
. Сброс установленного флага события в EXTI_PR.
. Подключение обработчика прерывания в NVIC.

Пример кода:

[source,cpp]
----
RCC::AHB1ENR::GPIOCEN::Enable::Set();
GPIOC::MODER::MODER13::Input::Set();

RCC::APB2ENR::SYSCFGEN::Enable::Set();
SYSCFG::EXTICR4::EXTI13::Value2::Set();

EXTI::FTSR::TR13::Value1::Set();
EXTI::RTSR::TR13::Value0::Set();
EXTI::PR::PR13::Value1::Set();
EXTI::IMR::MR13::Value1::Set();

NVIC::ISER1::Write(1 << 8U); // EXTI15_10
----

== Обработка нажатия кнопки

Функция обработки прерывания реализована внутри класса `ButtonExti` и связана с вектором EXTI15_10. В ходе выполнения проверяется, действительно ли сработала линия EXTI13, затем вызывается метод смены режима и очищается флаг события:

[source,cpp]
----
template<auto &modeManager>
class ButtonExti {
public:
    static void HandleClick() {
        if (EXTI::PR::PR13::Value1::IsSet()) {
            modeManager.SwitchModeManager();
            EXTI::PR::PR13::Value1::Set();
        }
    }
};
----

== Таймер: периодическая синхронизация

Для обновления состояния системы используется таймер `TIM5`, который настроен на генерацию прерывания с интервалом 500 мс. При каждом срабатывании вызывается метод `UpdateModeManager`, что позволяет визуально наблюдать за изменениями в активном режиме (например, мигание светодиодов).

[source,cpp]
----
TIM5::PSC::Write(SystemCoreClock / 1000U);
TIM5::ARR::Write(500U);
TIM5::DIER::UIE::Value1::Set();
TIM5::CR1::CEN::Enable::Set();
----

== Векторная таблица прерываний

В процессе компиляции формируется таблица векторов, где обработчики привязываются к соответствующим точкам входа. Прерывание EXTI13 относится к общей группе `EXTI15_10`. В таблице векторов определены следующие связи:

[source,cpp]
----
ButtonExti<modeManager>::HandleClick,     // EXTI15_10
Timer<TIM5, modeManager>::OverloadHandler // TIM5
----

== Демонстрация работы

После загрузки прошивки светодиоды начинают работать в одном из режимов. Каждый раз, когда нажимается кнопка, происходит переключение на следующий режим. Переполнение таймера `TIM5` инициирует обновление состояния текущего режима, создавая визуальную анимацию.

== Преимущества использования EXTI

* Мгновенное реагирование на события без задержек.
* Отсутствие необходимости в опросе входных сигналов в цикле.
* Освобождение процессора для выполнения других задач.
* Лёгкость в масштабировании: можно добавлять новые прерывания без изменения основного кода.

== Заключение

В данной работе разработана система обработки нажатий кнопки с использованием внешнего контроллера прерываний EXTI13 на микроконтроллере STM32F411. Применение шаблонного программирования и модульной структуры позволило создать компактное, расширяемое и эффективное решение. Данный подход демонстрирует метод разработки событийно-ориентированных встраиваемых приложений и может быть легко адаптирован для работы с другими источниками событий и режимами.

[source,cpp]
----
//main.cpp
int __low_level_init(void) {
    RCC::CR::HSION::On::Set();
    RCC::CFGR::SW::Hsi::Set();
    RCC::APB2ENR::SYSCFGEN::Enable::Set();
    STK::CTRL::CLKSOURCE::CpuClock::Set();
    RCC::APB1ENR::TIM5EN::Enable::Set();
    RCC::AHB1ENR::GPIOAEN::Enable::Set();
    RCC::AHB1ENR::GPIOCEN::Enable::Set();

    GPIOA::MODER::MODER5::Output::Set();
    GPIOC::MODER::MODER5::Output::Set();
    GPIOC::MODER::MODER8::Output::Set();
    GPIOC::MODER::MODER9::Output::Set();
    GPIOC::MODER::MODER13::Input::Set();

    SYSCFG::EXTICR4::EXTI13::Value2::Set();
    EXTI::FTSR::TR13::Value1::Set();
    EXTI::RTSR::TR13::Value0::Set();
    EXTI::PR::PR13::Value1::Set();
    NVIC::ISER1::Write(1 << 8U);   // EXTI15_10
    NVIC::ISER1::Write(1 << 18U);  // TIM5

    const auto TimerDivider = SystemCoreClock / 1'000U;
    TIM5::PSC::Write(TimerDivider);
    TIM5::CR1::URS::Value1::Set();
    TIM5::ARR::Write(500U);
    TIM5::SR::UIF::Set(0);
    TIM5::CNT::Write(0);
    TIM5::DIER::UIE::Value1::Set();

    return 1;
}

int main() {
    EXTI::IMR::MR13::Value1::Set();
    TIM5::CR1::CEN::Enable::Set();
    modeManager.InitModeManager();
    for (;;) {}
    return 1;
}
----

template<typename TIMRegs, auto &modeManager>
class Timer {
public:
    static void OverloadHandler() {
        if (TIMRegs::SR::UIF::InterruptPending::IsSet()) {
            modeManager.UpdateModeManager();
            TIMRegs::SR::UIF::Set(0);
        }
    }
};
----
